# windows-use

`windows-use` MCP 서버의 도구(`mcp__windows-use__*`)로 Windows 프로그램을 다룬다.
좌표는 모두 **물리 픽셀 화면 좌표**다. 모니터가 여러 대면 음수 좌표도 나온다(`screen_info`).

## 기본 순서

1. **창 찾기**: `list_windows` (process·title로 거르기, 늦게 뜨는 창은 `wait_ms`)
2. **요소 보기**: `ui_find`(조건으로 찾기)를 먼저 쓰고, 구조를 모를 때만 `ui_tree`(depth·max_nodes를 작게)
3. **다루기**: 받은 `ref`(e12 같은 것)로 `ui_read` · `ui_set_value` · `ui_click`
4. **확인**: 결과 메시지를 읽고, 화면이 바뀌는 동작 뒤에는 `ui_find`나 작은 `screenshot`으로 확인

창은 `hwnd`로 지정하는 것이 가장 정확하다. `process`·`title`로 지정하면 맞는 창 중 맨 앞의 창이 잡힌다.

## 수단 고르기 (위에서부터 시도)

| 순서 | 수단 | 언제 |
|---|---|---|
| 1 | `ui_find`/`ui_tree` (UIA) | 대부분의 앱: Win32, WinForms, WPF, UWP, 메모장, 탐색기, Office, Chrome 바깥 틀 |
| 2 | `backend: "win32"` | UIA 결과가 비거나 빈약할 때, **다른 가상 데스크톱 창**, WinForms 컨트롤의 `Name`(btnSave)이 필요할 때 |
| 3 | `screenshot` → `ui_at(x,y)` | 화면에서 본 것의 ref가 필요할 때 |
| 4 | `screenshot` → `mouse` 좌표 클릭 | 요소 정보가 전혀 없는 화면(직접 그리는 UI, 원격 화면, 게임) |
| 5 | `find_image` | 같은 그림을 반복해서 찾을 때 (`screenshot`의 `save_path`나 `ref`로 템플릿 저장) |

모니터가 여러 대면 전체 화면을 찍지 말고 `monitor`나 창을 지정한다(전체를 한 장으로 줄이면 글자가 안 읽힌다).

텍스트 결과가 스크린샷보다 훨씬 싸고 정확하다. 스크린샷은 처음 화면을 파악할 때와 결과를 확인할 때 쓰고, `max_size`를 800~1000 정도로 줄여도 대개 충분하다.

## 스크린샷 좌표 바꾸기

`screenshot` 결과에는 식이 같이 나온다. 예: `배율 0.5 → 화면 x = 100 + 이미지x / 0.5`.
이미지에서 본 위치를 `mouse`나 `ui_at`에 넘기기 전에 **반드시 이 식으로 화면 좌표로 바꾼다**.

## 값 넣기·누르기 요령

- `ui_set_value`는 값을 직접 넣고(안 되면 전체 선택 후 타이핑), **실제로 들어간 값을 다시 읽어 알려 준다**. "주의: 넣은 값과 다름"이 나오면 화면을 확인한다(서식이 바뀌었거나 입력이 막힌 경우).
- 값을 직접 넣으면 커서가 맨 앞으로 갈 수 있다. 뒤에 덧붙이려면 `press_keys ["Ctrl+End"]` 뒤 `type_text`.
- 글자 입력은 `type_text`를 쓴다. 한/영 상태와 상관없이 그대로 들어간다. `press_keys`로 글자 키를 누르면 한글 모드에서 한글로 바뀌니 단축키에만 쓴다.
- `ui_click`은 먼저 마우스 없이 누르고(Invoke·Toggle·Select·BM_CLICK), 거부되면 창을 앞으로 가져와 마우스로 누른다.
  - "비활성 상태라 누를 수 없음" → 화면이 아직 준비 중이다. 잠시 뒤 `ui_find`로 다시 찾아 누른다.
  - "눌렸을 수도 있으니…" → **다시 누르지 말고** 먼저 화면을 확인한다(두 번 눌리면 저장·전송이 두 번 될 수 있다).
- 목록·트리·탭 항목에 `ui_click`을 쓰면 "선택"만 된다. 열려면 `button: "double"`.

## 함정

- **늦게 뜨는 창·요소**: 실행 직후나 버튼을 누른 직후에는 아직 없을 수 있다. `list_windows`·`ui_find`·`find_image`의 `wait_ms`(예: 5000~15000)로 기다린다. `sleep` 대신 이것을 쓴다.
- **ref는 그때의 요소**다. 화면이 다시 그려지거나 창이 다시 열리면 "ref를 모름"이나 "요소가 사라짐"이 나온다. 그때는 다시 찾는다.
- **실행한 프로세스와 창의 프로세스가 다를 수 있다**: 메모장처럼 다른 프로세스로 넘기는 앱이 있다. `launch`가 돌려준 "새 창"의 hwnd를 쓴다.
- **최소화된 창**은 찍히지 않는다. `window` `restore` 후 찍는다.
- **다른 가상 데스크톱의 창**: 목록에 `다른-가상-데스크톱`으로 표시된다. 스크린샷(창 그림)과 `backend: "win32"` 읽기는 그대로 된다. 하지만 `focus`나 마우스 클릭은 **사용자 화면을 그 데스크톱으로 바꿔 버리니** 꼭 필요할 때만 쓴다.
- **관리자 권한 앱**: 목록에 `관리자권한(…조작 불가)`이 붙으면 이 서버도 관리자 권한으로 실행되어야 읽고 조작할 수 있다. `screen_info`에서 서버 권한을 확인한다.
- **가려진 창**: `screenshot`의 기본값은 창 자체 그림이라 가려져도 찍힌다. 일부 앱(GPU 렌더링)은 빈 그림을 줘서 화면에서 잘라낸 것으로 대신하는데, 그때는 위에 덮인 창이 찍힌다. 결과 문구를 확인한다.
- **줄바꿈**: RichEdit(메모장 등)는 줄바꿈을 `\r`로 저장한다. `ui_read`는 `\n`으로 바꿔서 돌려준다.
- **UIA 이름은 표시 글자**다. 값을 보여 주는 라벨은 이름이 계속 바뀌니 `automation_id`(WinForms는 `backend: "win32"`의 `name=`)로 찾는 것이 안정적이다.

## 안전

- 이 도구는 **사용자의 실제 PC**를 조작한다. 포커스를 가져가거나 마우스를 움직이면 사용자의 작업을 방해하니, 여러 단계를 조작하기 전에 무엇을 할지 짧게 알린다.
- 저장하지 않은 문서 닫기, 삭제, 전송·결제·제출 버튼, 설정 변경처럼 되돌리기 어려운 동작은 **먼저 사용자에게 확인**한다.
- 비밀번호 칸은 읽지 않는다(`ui_read`도 막아 둠). 사용자가 직접 요청하지 않으면 비밀번호를 입력하지 않는다.
- 화면과 창 내용에는 개인정보(고객 정보 등)가 있을 수 있다. 필요한 만큼만 읽고, 외부로 보내지 않는다.

## 예시

메모장에 글 쓰고 저장:
```
launch {path:"notepad.exe"}                       → 새 창 hwnd=123
ui_find {hwnd:123, control_type:"Document"}       → e1
ui_set_value {ref:"e1", value:"내용"}
press_keys {hwnd:123, keys:["Ctrl+S"]}
list_windows {title:"다른 이름으로 저장", wait_ms:5000}
```

WinForms 앱에서 값 읽기:
```
list_windows {process:"MyApp"}                    → hwnd=456
ui_find {hwnd:456, automation_id:"txtName"}       → 없으면 ↓
ui_find {hwnd:456, backend:"win32", automation_id:"txtName"}
ui_read {ref:"e5"}
```

요소 정보가 없는 화면:
```
screenshot {hwnd:789, max_size:1000}              → 식: 화면 x = 10 + 이미지x / 0.5
mouse {x: 10 + 240/0.5, y: 20 + 130/0.5}
```
